## 3. 数据设计（SQLite 数据字典）

约定：主键 `INTEGER PRIMARY KEY AUTOINCREMENT`；时间戳 `TEXT`（ISO8601）；开启 `PRAGMA foreign_keys=ON`；schema 用 `schema_migrations` 表管理增量迁移。

### 3.1 一期表

**categories**

| 列 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | INTEGER PK | |
| name | TEXT NOT NULL | ≤20 字符，应用层校验 |
| color | TEXT NOT NULL | `#RRGGBB` |
| sort_order | INTEGER NOT NULL | 标签栏顺序 |
| kind | TEXT NOT NULL | `normal` / `uncategorized`（总览是聚合视图，不落库） |

**items**

| 列 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | INTEGER PK | |
| category_id | INTEGER NOT NULL FK→categories | 未分类也落库为一条分类记录 |
| title | TEXT NOT NULL | ≤100 字符 |
| description | TEXT NULL | |
| start_date / end_date / due_date | TEXT NULL | `YYYY-MM-DD`，可空 |
| start_time / end_time / due_time | TEXT NULL | `HH:MM`，可空；日期为空则时刻必须为空 |
| created_at | TEXT NOT NULL | ISO8601，默认当前时间；待办“同时刻按创建时间”排序兜底（PRD 5.2） |

- **归属规则不落库**（无 location 列），由查询条件表达，避免冗余状态：
  - 日历集合：`start_date IS NOT NULL AND end_date IS NOT NULL`
  - 待办集合：`start_date IS NULL OR end_date IS NULL`
  - 待办排序：`COALESCE(due_date,'9999-12-31') ASC, COALESCE(due_time,'00:00') ASC, created_at ASC`（无截止=沉底，与 PRD 5.2 一致）
- 索引：`idx_items_cat(category_id)`、`idx_items_dates(start_date, end_date)`、`idx_items_due(due_date, due_time)`。
  - 窗口交集查询条件为 `start_date <= ? AND end_date >= ?`（双向区间），单一复合索引无法同时高效服务两个方向。工程初始化后以万级数据实测为准（PRD 9：月视图切换 <300ms）；不达标时拆为 `idx_items_start(start_date)` 与 `idx_items_end(end_date)` 两个单列索引并复测。

**field_defs**

| 列 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | INTEGER PK | |
| category_id | INTEGER NOT NULL FK→categories ON DELETE CASCADE | |
| name | TEXT NOT NULL | |
| type | TEXT NOT NULL | `text` / `multiline` / `number` / `date` / `single_choice` / `multi_choice` |
| options_json | TEXT NULL | 仅单选/多选：`["选项1","选项2"]` |
| sort_order | INTEGER NOT NULL | |

**item_field_values**

| 列 | 类型 | 说明 |
| :--- | :--- | :--- |
| item_id | INTEGER FK→items ON DELETE CASCADE | 联合主键 (item_id, field_def_id) |
| field_def_id | INTEGER FK→field_defs ON DELETE CASCADE | 联合主键 (item_id, field_def_id) |
| value_json | TEXT NULL | 统一 JSON：文本/数字/日期存标量；多选存字符串数组 |

**app_settings**

| 列 | 类型 | 说明 |
| :--- | :--- | :--- |
| key | TEXT PK | |
| value | TEXT | 一期：视图偏好（周/月）等；二期扩展“上次同步时间”等用途 |

- 删除字段定义 → 级联删除对应值（对应 PRD 6.5 的二次确认与数据丢失提示）。
- **切换事项所属分类不迁移字段值**：值行保留，展示层按"当前所属分类的 field_defs"过滤（对应 PRD 4.3"保留但不再显示"）。
- **删除分类（移入未分类，决策 A / PRD 6.2 v1.7）**：该分类 field_defs 级联删除、其值随之清除；事项标准字段保留并改挂未分类（与 ON DELETE CASCADE 一致）。

### 3.2 二期表

- **reminders**：id、item_id FK（ON DELETE CASCADE）、`remind_at TEXT('YYYY-MM-DD HH:MM')`、content。一个事项可多条；到点弹窗关闭即视为已处理，无 done 状态（PRD 8.4 v1.4）。
- **mail_config**（单行表 id=1）：smtp_host、smtp_port、encryption(`ssl`/`starttls`)、account、sender_name、`auth_code_cipher`（DPAPI 密文 base64）。
- **send_queue**：id、reminder_id FK（ON DELETE CASCADE）、`planned_send_at`、status(`pending`/`sent`/`failed`/`expired`)、last_error。
  - 「同步」= 幂等重建：将未来 30 天窗口内的提醒重建为 `pending` 计划，窗口外与已完成的不动。
  - **状态机（PRD 8.4 v1.4）**：到点发送失败 → `failed`（**不自动重试**，无 retry_count）；用户在「提醒发送记录」手动重试 → `failed→pending` 重新入队；启动检测仅将 `pending` 且已到点置 `expired`（不补发，不可重试）；`failed` 重启后保持原状。

### 3.3 备份 JSON 结构

```json
{
  "format_version": 1,
  "exported_at": "ISO8601",
  "categories": [],
  "field_defs": [],
  "items": [ { "...": "标准字段", "field_values": [] } ],
  "reminders": [],
  "app_settings": {}
}
```

- 备份文件**不含授权码**（决策 D8）；导入后若库中已有邮箱配置则保留原配置，否则需重新绑定。
- 导入 = 整库替换，导入前快照入撤销栈（PRD 6.7/6.8）。
- **导入语义校验**：与新增/编辑同级校验（标题非空、结束日期不早于开始、日期与时刻成对、单选值在选项内等），任一违规即拒绝整次导入并提示具体错误，当前数据不变（对应 TC-BAK-006；TC-BAK-004 仅覆盖损坏/非法 JSON）。

## 5. 关键技术设计

### 5.1 日历横条布局算法（前端纯函数）

输入：可见范围 `[viewStart, viewEnd]`、月视图周行数（5~6）、事项数组（起止日期、开始时刻、标题、分类色）。

1. 每个事项与可见范围求交集，交集为空剔除。
2. 按周行切分：事项在每个周行内得到分段 `[segStart列, segEnd列]`（0~6），每个周行独立布局。
3. 周行内贪心泳道分配：按 `(segStart, start_time, segEnd, id)` 排序（`start_time` 为开始时刻字符串，无时刻归一为 `00:00`），依次放入该区间内未被占用的最小泳道号；由此同一格内多条横条自上而下按开始时间升序、相同按创建顺序（对应 PRD 5.3 v1.4 / TC-CAL-011）。
4. 输出 `{rowIndex, startCol, span, lane}` → 绝对定位渲染（top=lane×行高，left=startCol×列宽，width=span×列宽）。
5. `+N`：每格最大泳道数 = ⌊格高/行高⌋−1；被截断的事项计入该格 +N 计数；点击 +N 打开当日事项浮层。

复杂度 O(n log n)；参与布局的只有可见窗口内的事项（见 5.2），万级数据无压力。

### 5.2 数据按需查询
- 切换周/月/标签页时调用 `query_calendar(view_start, view_end, category_id?)`：仅返回与窗口有交集的事项，不做全量加载。
- 待办：`query_todo(category_id?)` 返回待办集合元数据（id/标题/截止/分类色）；列表前端虚拟滚动（自实现简易虚拟列表，不引库）。

### 5.3 撤销栈（Rust undo 模块）

```rust
trait Command: Send {
    fn apply(&self) -> Result<()>;   // 重做时执行
    fn revert(&self) -> Result<()>;  // 撤销时执行
    fn describe(&self) -> String;
}
```

- 双栈实现：`Vec<Box<dyn Command>>`（撤销）+ 重做栈；新操作入栈时清空重做栈；上限 10 步，超出丢弃最旧。
- 实现方式统一为**受影响行变更前后快照**：删除/更新存整行（含字段值行）；删除分类存分类+事项+字段定义+值全量快照（级联）；改字段类型存受影响 value 前值与旧 options_json；导入备份存导入前整库 JSON 快照。
  - **导入快照剔除 mail_config**（决策 D10）：授权码密文不进入撤销内存。
  - **大快照落临时文件**（决策 D10）：整库快照序列化后写入 `data\undo_tmp\`，内存仅存路径；应用退出/重启时清理该目录（撤销栈本就重启清空，PRD 6.7）。
- IPC：`undo()` / `redo()` / `undo_depth()`；前端监听深度变化刷新按钮态。
- 快捷键：前端 window keydown 监听 Ctrl+Z / Ctrl+Y；`document.activeElement` 为 input/textarea/contenteditable 时不触发（文本级撤销交给输入框，PRD 6.7）。

| items（一期） | create / update / delete / get_detail / query_calendar(view_start, view_end, category_id?) / query_todo(category_id?) |

### 5.5 二期邮件与调度
- **mailer**：lettre 按 encryption 配置建立 TLS 连接；发送失败置 `failed` 并 emit 事件（**不自动重试**，PRD 8.4 v1.4）；用户经 `retry_send(id)` 手动重试（`failed→pending` 重新入队）。
- **scheduler**：tokio interval 30s 扫描 `status='pending' AND planned_send_at<=now`：触发 `reminder-due`（弹应用内置顶提醒弹窗）+ 在发送计划内则发邮件。
- **启动检测**：仅 `status='pending' AND planned_send_at<now` → 批量置 `expired`（不补发，不可重试）；`failed` 重启后保持原状，可在发送记录手动重试；emit `expired-reminders` 前端弹窗汇总告知（PRD v1.1/v1.4）。
- **未配置邮箱**：mailer/scheduler 不启动，相关命令返回"未绑定"，保证零网络（PRD 8.5）。
- **稍后 10 分钟**：更新 remind_at=now+10min 并重新进入弹窗调度；邮件仅在原计划未发送且未过期时顺延计划（顺延后仍在计划内，无需再次同步）。
- 系统休眠/唤醒：唤醒后首次扫描按实际时间执行；错过的直接按过期处理（与上条一致，不补发）。
- **并发模型（B5）**：rusqlite 为同步 API，所有涉库的 async command 一律 `tauri::async_runtime::spawn_blocking` 执行，避免阻塞 async runtime；scheduler 30s 扫描与用户操作共用单连接 Mutex，扫描内使用短事务，严禁在持锁期间执行 SMTP 网络 IO。

### 5.6 安全与隐私
- 默认零网络：一期无网络依赖；二期仅「发送测试邮件」「计划内到点发送」两条路径联网，全程 TLS（拒绝明文 SMTP 配置）。
- 授权码 DPAPI（CurrentUser 作用域）加密，密文仅存本机库；备份不含授权码；日志脱敏（不打授权码与邮件正文）；撤销/导入快照亦剔除授权码（决策 D10）。
- **密文解不开的降级**（决策 B4）：检测到 DPAPI 密文无法解密（换机/换用户拷贝 data\ 目录等场景）时，给出友好提示并引导重新绑定，不清空数据、不崩溃（README 说明：整目录拷贝后需在新机器重新绑定邮箱）。

### 5.7 打包与便携
- **分发形态（决策 D11）**：便携绿色目录 = 主 exe + `webview2\`（WebView2 Fixed Version Runtime 解压目录）随 zip/7z 发布，拷贝即用；首次启动在 exe 同目录创建 `data\`，目录不可写则弹提示引导移动。
- **WebView2 免预装（决策 D11）**：`main.rs` 最顶部检测系统 Evergreen runtime（读注册表 `HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}` 的 `pv`，或调用 WebView2Loader 的 `GetAvailableCoreWebView2BrowserVersionString`）；缺失时在创建任何 WebView **之前** `set_var("WEBVIEW2_BROWSER_EXECUTABLE_FOLDER", exe_dir/webview2)` 指向捆绑固定版（wry 读取该内置环境变量定位 runtime，Tauri 官方机制）。Fixed Version 运行时约 +150~180MB（x64），用户已确认放宽体积；从微软官网下载 zip 解压，升级=替换 exe 与 `webview2\` 目录（无自动更新，符合离线红线）。
- 兜底：捆绑目录缺失且系统无 Evergreen runtime（拷贝不全）→ 启动提示补齐 `webview2\`。
- 不做自动更新（免安装+离线原则）；升级=替换 exe 与捆绑目录，schema 增量迁移自动完成。

## 7. 风险与对策

| 风险 | 对策 |
| :--- | :--- |
| WebView2 缺失 | 默认捆绑 Fixed Version Runtime（D11），零预装；兜底：捆绑目录缺失且系统无 Evergreen 时提示补齐 `webview2\` |
| exe 所在目录只读 | 启动检测可写性，弹提示引导移动 |
| 跨月/跨年横条边界 bug | 布局纯函数化 + 边界单测（对应 TC-CAL-005） |
| 转换矩阵实现遗漏路径 | (from, to) 枚举表驱动 + 穷举单测 |
| SQLite 并发写 | 单连接 + Mutex 串行化 + 单实例互斥（D9）；async command 经 spawn_blocking（B5） |
| 提醒调度误差（休眠/关机） | 唤醒后按实际时间扫描；错过的置 expired 不补发；发送失败置 failed 供手动重试（PRD v1.4） |
| 万级性能目标不达标 | 窗口交集索引策略（3.1）+ 工程初始化时以万级实测验收（PRD 9 <300ms） |
| 置顶提醒弹窗 / 托盘（二期） | 真机验证 Win10/Win11 的 topmost 与焦点行为，列入二期验收清单（B7） |
